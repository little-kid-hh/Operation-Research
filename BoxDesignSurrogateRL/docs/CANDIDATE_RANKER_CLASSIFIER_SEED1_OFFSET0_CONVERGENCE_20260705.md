# Candidate Classifier Ranker Seed1 Offset0 Convergence Comparison, 2026-07-05

## Purpose

Run the first true seed-specific initial-condition replicate of the
shared-cache convergence-path protocol. Unlike the seed-0 five-window result,
this run does not pass a fixed `--initial-boxes-json`; exact staged generates
the initial K=10 box set by k-means with `--seed 1`, and the ranker+audit path
reuses that exact run's `initial_boxes.json`.

The comparison answers:

> Under a different initial box set on test[0,100), can a time-budgeted learned
> ranker followed by exact audit match or improve exact staged convergence
> while using fewer exact MILP oracle resources?

## Main Comparison

The ranker path plus exact audit reaches slightly better final PF than exact
staged from the same seed-1 initial boxes, while preserving full coverage.

The cost comparison favors the ranker path:

- 24.5% fewer MILP candidate validations.
- 13.6% fewer uncached boxes.
- 13.3% lower Java/Gurobi subprocess time.
- 13.7% lower wall-clock time.

The ranker-only 180-second phase stopped at PF `2.0194023691` with full
coverage. The exact audit then continued from those boxes to PF
`1.8892309108`.

## Interpretation

This is the first evidence beyond the seed-0 fixed-checkpoint protocol. It is
still only one additional initial-condition replicate, but it is strongly
positive: exact-verified ranker search finds a path to a slightly better local
solution than exact staged, and it does so with less measured oracle work.

The next step is to replicate this seed-specific protocol across the remaining
100-order windows and additional seeds before claiming statistical
significance.
